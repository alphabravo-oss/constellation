============================================================================
CloudNativePG (cnpg) mode
============================================================================
This release expects the CloudNativePG operator to be running cluster-wide.
The chart does NOT bundle the operator or its CRDs (postgresql.cnpg.io). If the
Postgres Cluster is stuck Pending, the operator is almost certainly not
installed — install it once, then `helm upgrade` this release:

  kubectl apply --server-side -f \
    https://raw.githubusercontent.com/cloudnative-pg/cloudnative-pg/release-1.24/releases/cnpg-1.24.1.yaml

The operator reconciles Cluster "{{ include "constellation.fullname" . }}-postgres"
and auto-creates the services -postgres-rw / -ro / -r. The app DSN targets
the -rw (primary) service. Watch bootstrap with:

  kubectl -n {{ .Release.Namespace }} get cluster {{ include "constellation.fullname" . }}-postgres -w

The findings schema declares `embedding vector(1536)`, so the operand image
MUST ship the pgvector extension. The default CNPG image does NOT. Migrations
that create the vector column WILL FAIL against a non-pgvector image.

Supply a pgvector build, e.g. build FROM ghcr.io/cloudnative-pg/postgresql:16
plus `postgresql-16-pgvector`, then set:

  --set postgres.cloudnativepg.imageName=<your-registry>/cnpg-pgvector:16

See examples/values-cnpg.yaml for a ready-made profile. (This is a heuristic
check on the image ref — if your pgvector image simply lacks "pgvector" in its
name, you can ignore this warning.)

{{- if .Values.auth.local.bootstrap.enabled }}
Local accounts are enabled by default. On first boot, an initial administrator is
created only when no normal local accounts exist. Email: {{ .Values.auth.local.bootstrap.email }}.
Password and TOTP enrollment seed are stored in Secret
{{ .Values.auth.local.bootstrap.existingSecret | default (printf "%s-local-admin" (include "constellation.fullname" .)) }}.
Retrieve privately (these commands print credentials):
  kubectl -n {{ .Release.Namespace }} get secret {{ .Values.auth.local.bootstrap.existingSecret | default (printf "%s-local-admin" (include "constellation.fullname" .)) }} -o jsonpath='{.data.password}' | base64 -d
  kubectl -n {{ .Release.Namespace }} get secret {{ .Values.auth.local.bootstrap.existingSecret | default (printf "%s-local-admin" (include "constellation.fullname" .)) }} -o jsonpath='{.data.totp-secret}' | base64 -d
Enroll the seed in an authenticator (TOTP, SHA1, 6 digits, 30 seconds) before signing
in. Use another administrator in Settings > Users, or constellationctl users, to
reset enrollment/password after securely handing them to the administrator. On a new install this administrator is also the one recovery
account. Upgrades preserve the existing recovery administrator and its credentials.
The generated Secret is retained across upgrades; it never resets database users.
{{- end }}
Sign-in policy is editable in Settings > Sign-in methods. Changing auth.local or
auth.oidc chart values replaces the saved policy on API startup; unchanged values
preserve admin edits. Disabling local sign-in revokes normal local sessions.
