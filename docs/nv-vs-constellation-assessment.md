## Executive Summary

This assessment maps Constellation's console against NeuVector (NV) across **12 functional areas** and surfaces roughly **200 discrete gaps** — 3 critical, ~55 high, ~110 medium, and the balance low. The headline finding is that Constellation is **architecturally ahead but presentationally and interactively behind**: its data model, multi-tenant RBAC, audit integrity, and correlation engine consistently exceed NV, while the console fails to expose data the backend already holds and stops short of the day-2 operator actions NV ships.

**Where Constellation clearly leads.** The vulnerability stack is richer than NV's on every axis that matters for triage — KEV/EPSS as first-class signals, a browsable 332k-row CVE catalog independent of scans, cross-engine (Trivy+Grype) reconciliation with disagreement signals, reachability analysis, composite risk decomposition, and a full accept-risk/exceptions workflow with separation-of-duties. Compliance ships 17 frameworks (vs NV's ~7), cosign-signed scheduled evidence, SARIF output, and CEL custom checks. Notifications dwarf NV (Slack/Jira/ServiceNow/PagerDuty + routing tree + delivery ledger vs NV's webhook+syslog). The audit log is hash-chained and verifiable; the network layer has SSE streaming, multi-source flow provenance, and a convert-to-NetworkPolicy lifecycle NV cannot match. Everything is org- and cluster-scoped for multi-tenancy where NV is single-cluster.

**The three critical gaps** are all *conceptual absences*, not polish: (1) **Groups + Network Rules** — Constellation has no ordered, readable/editable network rule object at all; "policy" is a per-workload allow-list generator with no rule row, no deny, no order. (2) **Process baselines** — no process allow/deny rule CRUD (file profiles got it; process didn't). (3) **Admission Control** — no global enable/monitor/protect state surface; admission is YAML-only with no rule builder.

**The dominant theme** across the high/medium tier is **backend-present, UI-absent or UI-truncated**: hard `LIMIT` caps with client-side pagination on nearly every list, raw-JSON dumps where NV renders tables, existing endpoints (host scan-now, host-CIS pages, admission assess, registry images, vuln_profiles) that no page calls, and server-side filters that are silently ignored. Closing these is largely wiring and rendering work against data Constellation already produces — high leverage per unit effort.

Net posture: Constellation would win a data-depth and governance bake-off today but loses an operator-experience demo. The backlog below front-loads the critical rule-object gaps, then the cross-cutting list/export/filter debt that spans 8+ areas.

## Cross-Cutting Themes

These recur across areas; fixing them once (shared component/query pattern) closes many findings at once.

- **Hard `LIMIT` caps + client-side pagination/sort/filter (silent truncation).** No server-side `start/limit/sort/filter` on almost any list. Nodes cap at `LIMIT 500`; network conversations `5000` / map flows `300`; registry images `500`; findings fetch `limit:500` (instances) / `2000` (by-CVE) and filter in-browser; Groups, Process/File, Admission, and Security-Events lists load-all-then-sort. On busy clusters rows past the cap are **invisible with no pager**. Spans: Nodes, Network, Containers, Registries, Vulnerability, Groups, Process/File, Admission/DLP, Security Events.

- **Backend exists, UI never calls it (dead endpoints).** `POST /scan/host/{id}` (jobs.TriggerHost) has no button; `/host-cis` + `/host-cis/{node}` have no page; `POST /policies/assess` (admission dry-run) has no tab; `/registries/{id}/images` is unused so registries are a dead-end list; `vuln_profiles` CRUD + pkg/vulnprofile eval exist but the `/findings` query never references them. Spans: Nodes, Compliance, Admission, Registries, Vulnerability.

- **Raw JSON blobs instead of structured tables.** NodeDetailPage dumps host facts/packages/containers/processes as `<pre>` JsonPanels (and renders Host facts twice — a bug at NodeDetailPage.tsx:76-81). NV renders these as lists. Spans: Nodes (primary), Containers.

- **Server-side filters silently ignored / free-text runs client-only.** `/network/conversations` ignores namespace + verdict selects (only honors hours+cluster_id). FindingsPage's text box runs `clientFilter()` over the fetched page; the DSL `q` exists but isn't wired. Spans: Network, Vulnerability.

- **Missing CSV/PDF export.** No ad-hoc export on Dashboard, Nodes, Containers, Registries image reports, Vulnerability by-CVE/catalog, Compliance page tables, Process/File rules, DLP/response lists, or Security Events. Constellation has only `/findings.csv` and scheduled artifacts. NV exports nearly every table. Spans: all 12 areas.

- **Accept/whitelist "show accepted" not wired.** No show-accepted toggle for image CVEs, host CVEs, or findings even though vuln_profiles exist. Spans: Registries, Nodes, Vulnerability.

- **Policy-mode / profile-mode (Discover/Monitor/Protect) not surfaced.** Not a node column, not a workload Status column, not a graph node badge, not a dashboard pie. Constellation tracks modes inside baselines but never as a first-class posture column. Spans: Dashboard, Network, Nodes, Containers.

- **CVSS score/vector absent from list rows.** `/findings`, by-CVE, and host-vuln rows expose only composite risk_score; cvss_base/vector/score_v3 live in cve_records but aren't joined. Spans: Vulnerability, Nodes, Registries.

- **Rule ordering / precedence missing.** No reorder for network rules, no process rule order, response_rules_v2 sorts alphabetically. Spans: Groups, Process/File, Admission.

- **Regulation mapping (tags_v2) + remediation dropped in render.** Compliance parses remediation (kubebench.go:50) then discards it; tags_v2 returned but never displayed; host CIS is `{id,title,result,detail}` only. Spans: Compliance, Nodes.

- **YAML export/import for GitOps, piecemeal.** Present for admission profiles and file profiles; absent for Groups, DLP/WAF/response rules, vuln profiles, compliance profiles, process baselines. Spans: Groups, Admission/DLP, Vulnerability, Compliance, Process/File.

- **Aggregate-only, no individual object.** No live per-connection session row (Network), no individual container/pod inventory row or pod→container tree (Containers) — everything folds to service/deployment aggregates. Spans: Network, Containers.

- **Namespace/domain RBAC scoping of *results*.** Constellation gates by coarse verb; NV filters each row by the caller's namespace access. Spans: Groups, Security Events, Compliance, Settings/RBAC.

## Top Priorities (fix these first)

1. **[Groups + Network Rules] Ship a first-class ordered network-rule object (CRITICAL).** Constellation has no readable/editable rule row at all — build allow **and** deny rules with priority, enable/disable, and a reorder/move-to-top primitive. This is the single largest conceptual gap; everything else in Groups depends on it.

2. **[Process/File] Process allow/deny rule CRUD + baseline-strategy toggle (CRITICAL).** File profiles got rule CRUD; process baselines are mode-only. Add per-process Action (allow/deny), the zero-drift-vs-basic strategy control, and user/uid columns. Close the documented asymmetry.

3. **[Admission] Global admission state surface + criteria rule builder + wire dry-run (CRITICAL/high).** Add the enable/monitor/protect/failure-policy state panel and a dropdown-driven criteria rule editor (image/namespace/CVE-count/privileged/signed). The `/policies/assess` backend already exists — give it a test page.

4. **[Cross-cutting, all lists] Server-side pagination + sort + filter; kill the hard LIMIT caps.** Nodes 500, conversations 5000, map 300, registry images 500, findings 500/2000 all truncate silently. Ship one shared `start/limit/sort/filter` pattern and a total-records count. Correctness bug at scale spanning 8+ areas.

5. **[Vulnerability] Join CVSS base/vector/score_v3 into `/findings` and by-CVE; add a fixable (with-fix) server filter.** cve_records holds the data but isn't joined; rows show only composite risk_score. NV treats fix-availability and CVSS as primary triage axes.

6. **[Vulnerability] Wire the server-side quickFilter and vuln_profiles.** The text box runs clientFilter over one page — connect it to the existing DSL `q`. Reference vuln_profiles in the findings query and add a show-accepted toggle (CRUD + eval already exist).

7. **[Nodes] Replace raw JSON `<pre>` dumps with structured tables and fix the duplicate Host-facts panel (NodeDetailPage.tsx:76-81).** Render containers/processes/packages as lists like NV. Pure rendering work, high visible payoff.

8. **[Nodes] Wire the existing `POST /scan/host/{id}` to a Scan-now button.** jobs.TriggerHost exists; no UI calls it. Same "dead backend" fix pattern as items 3, 9, 10.

9. **[Compliance] Build the host/node CIS page.** `/host-cis` + `/host-cis/{node}` exist but no frontend reads them — host CIS results are entirely invisible today.

10. **[Compliance] Surface remediation (parsed then dropped at kubebench.go:50), render tags_v2 regulation mapping, and add a compliance-asset rollup (per-control across assets).** These three are NV's core compliance dashboard shape.

11. **[Registries] Make registries not a dead-end.** Wire RegistriesPage → `/registries/{id}/images` and enrich that endpoint with the scan brief (CVE counts, base_os, size, verdict, run_as_root) plus per-registry scan-progress counters (scanned/scanning/failed).

12. **[Registries + Vulnerability] Add the image Compliance/CIS-Docker checks tab and setid-perms card to the image report.** ImageScanDetailPage shows packages/layers/secrets/SBOM but no `checks[]` (RESTBenchItem) — a whole report tab NV ships.

13. **[Containers] Introduce an individual container/pod inventory row** (state/node/image/mode/privileged) with pod→container hierarchy. Today only aggregate deployments exist; NV lists every running container.

14. **[Containers] Add a policy_mode/profile_mode Status column and make privileged/run_as_root first-class fields** (derived from risk_factors JSON today). Feeds the cross-cutting mode-badge theme.

15. **[Network] Add per-conversation entry drilldown (port/app/policy/threat) and fix `/network/conversations` silently ignoring namespace + verdict filters.** The UI selects currently don't scope the server view.

16. **[Network + Containers] Surface quarantine as a graph node action and a per-workload button.** Constellation already has an audited quarantine model (quarantineDTO) — just expose it as the incident-response action NV offers.

17. **[Security Events] Add filter-driven CSV/PDF export, per-threat pcap download, and rich network columns** (client/server IP, application, action, count) on the events table.

18. **[Admission/Response] User-controlled response-rule evaluation order** (today alphabetical by name) **and the full event vocabulary** (threat/incident/violation/dlp/waf/cve-report), which the current admission|runtime|scan|compliance set can't target distinctly.

19. **[Settings/RBAC] Create-local-user + editable role permission matrix + LDAP/SAML/OIDC Test/discovery.** The Users and Roles tabs are display-only; there is no way to create a user outside SSO JIT, and no role editor.

20. **[Settings/RBAC] Configurable account lockout + per-character-class password minimums** in the security policy (only coarse min_classes today) — plus surface password-expiry and unlock actions.

21. **[Dashboard] Ship the PDF report, exposure CSV, a Security-Events timeline tab, and the system-summary counters strip.** These are the most-noticed missing dashboard affordances vs NV.

22. **[Cross-cutting export] Add YAML export/import for Groups, DLP/WAF/response rules, vuln profiles, compliance profiles, and process baselines** — GitOps portability that currently exists only for admission and file profiles.

23. **[Nodes] Collect and display per-host CPU count + total memory** (never collected today) and per-node enforcement policy mode — the most basic host facts NV shows on every row.

## Where Constellation Already Leads NeuVector

**Dashboard / Security Score**
- Security Risk Score and its 6-factor breakdown are computed server-side in internal/handler/dashboard.go computePosture (client cannot tamper), and the endpoint is RBAC-gated org-scoped via requireVerb(VerbReadFindings) — NV recomputes in-browser from fully-returned raw metrics.
- Exposure is correlated to a precomputed deployment risk_score and CVE counts via a direct LEFT JOIN in internal/handler/network/exposure.go, and every dashboard tile/row deep-links to a pre-filtered drill-down route (clusterPath).
- Constellation surfaces pillars NV's dashboard omits inline: a Compliance pass-% tile, a CVE Database provenance panel (bundle version, cosign signer identity, imported-at), and a Platform Scan panel with control-plane package evidence.
- Severity/lifecycle totals come from a single server-aggregated /dashboard/summary query rather than tallying a paginated findings list client-side, so critical/high counts stay consistent with their drill-downs at scale.

**Network Activity / Traffic Map (topology, conversations, sessions, exposure, protocol/application breakdown)**
- Live Server-Sent-Events flow stream (/network/flows:stream, internal/handler/network/stream_flows.go) — NeuVector has no push channel; its graph polls on a timer.
- Exposure + vulnerability correlation (/network/exposure, exposure.go): ingress/egress externally-reachable services joined directly to CVE critical/high/risk_score — NV's graph does not join reachability to scan data this tightly.
- Multi-source flow provenance with precedence (source: dp|hubble|bpf, network.go flows()): fuses DPI, Cilium/Hubble, and eBPF connect events — NV is DPI/enforcer-only.
- Convert-to-NetworkPolicy lifecycle in the inspector (approve/apply/demote/rollback) with native/cilium/calico manifest flavors (PolicyLifecyclePanel, NetworkMapPage.tsx).
- Correlated .pcap download tied to a flow's DPI threat, plus a unified 4-tab Flow/Threat/Policy/History inspector with a byte sparkline.
- Pre-aggregated network_flow_rollups (migration 115, rollup.go) so the graph scales to millions of raw flows without a full-day GROUP BY on every load.

**Nodes / Hosts (host list + host detail)**
- Org- and cluster-scoped multi-tenant node model (every query filtered by org_id+cluster_id); NV is single-cluster per controller
- Explicit coverage-gap tracking per node (host_facts/host_packages/host_vulnerability_scan/host_cis) — NV has no 'missing telemetry' signal
- Runtime-agent freshness as a first-class column (status/version/last-seen with healthy/stale/missing derivation + inventory hash)
- CIS results already rendered as a sortable fails-first table with remediation (CisBenchmarkTable) instead of a JSON blob
- Constellation-specific eBPF/NFQUEUE enforcement-readiness facts (btf_present, nfqueue_capable) that NV does not track

**Containers / Workloads / Groups list (per-running-container + workload inventory)**
- Deployment risk score + risk-factor bar (CVSS/KEV/EPSS/net-exposure/reachability) has no NV equivalent — NV shows only raw severity counts (DeploymentsPage.tsx FactorBar).
- Process baseline with promote/rollback transitions and 24h monitored-alert / enforced-block counts is cleaner than NV's process-profile UI (DeploymentDetailPage.tsx ProcessBaselinePanel).
- Digest-scoped image accept-risk with mandatory rationale, auto-expiry, revoke, and full audit history (AssetDetailPage.tsx) — NV has no per-image risk-acceptance workflow.
- SBOM export in SPDX / CycloneDX / MBOM directly from the asset (AssetDetailPage.tsx sbom.download*).
- Image file-risk findings (setuid/world-writable/secrets per layer) surfaced per deployment — deploymentFileRiskDTO — beyond NV's container detail.
- Network-policy lifecycle candidate + generated manifest inline on the deployment (DeploymentDetailPage.tsx network-policy card).
- Quarantine is audited with reason, expiry, lift history and org-scoped RBAC (VerbAcceptRisk / quarantineDTO), a richer model than NV's boolean toggle.
- Org-scoped multi-tenant RBAC on every endpoint (requireVerb) vs NV's single-cluster access model.

**Registries + Image Scanning**
- Finding data model is materially richer than NV's RESTVulnerability: EPSS probability, KEV flag, package PURL, aliases, multi-engine provenance, reconciliation signals, and canonical-engine dedupe (imageScanFindingDTO in internal/handler/image_scan_results.go).
- SBOM export in both SPDX and CycloneDX plus typed JSON artifact downloads (inventory/layers/secrets/file-risks/signature) — NV has no SBOM export.
- First-class Sigstore signature/attestation evidence (identity, issuer, Rekor log, trust policies) integrated into the image report and exposed via /image-scan-results/{id}/signature and /repository-scan-attestations.
- Inline running-workload exposure per image (impacted_count + /affected-workloads) so each scanned image shows the deployments it endangers, correlated in one query.
- Structured file-risk evidence panel (path, mode, uid/gid, risk types, layer) that is richer than NV's flat setid_perms list.
- Cluster-scoped image list filtering (cluster_id) that only shows images actually running in the selected cluster, tying scan results to live exposure.

**Vulnerability Views + CVE Detail + Accept/VEX**
- KEV + EPSS as first-class signals with dedicated badges, filters and stat tiles (NV exposes only feed_rating, no KEV/EPSS)
- Browsable 332k-row CVE catalog via /cve/search + /cve/stats that is independent of what has been scanned (NV only shows CVEs found in scans)
- Composite Constellation Risk Score with a full subfactor decomposition (risk.Decompose) returned on the finding detail
- Cross-engine reconciliation and provenance: Trivy+Grype results merged with canonical_engine, engines[] and reconciliation[] disagreement signals (disagreement:true DSL)
- Reachability analysis (static + runtime) surfaced as risk inputs and a reachable: DSL filter
- CVE nickname resolution (Log4Shell, Heartbleed, Spring4Shell, xz-backdoor ...) mapping human names to canonical CVE-IDs
- Accept-risk with enforced separation-of-duties, a 30-day expiry cap, mandatory >=12-char reason, and an audit-log trail
- Full vulnerability-exceptions workflow with requester/approver, expiry, business justification, compensating controls and review cadence — richer than NV's flat whitelist
- Multi-cluster blast radius (affected images + workloads + clusters with a cluster_id scope param)
- Search DSL over findings (severity/kind/package/purl/fixed/engine/reachable/disagreement/time ranges) shared across list + CSV
- SBOM download and finding comments/collaboration on each finding

**Compliance / CIS Benchmarks**

### Security Events, Notifications, Audit & Reports

#### What NeuVector shows/exposes

**UI (Manager → Notifications).** Three consoles plus a config surface:

- **Security Events** — a merged threat/violation/incident console with multiple display modes (Timeline *slider*, Grid/table, and a network-graph correlation view). Table columns include timestamp, severity (color-coded), event name/type, source (client workload/IP + port), destination (server workload/IP + port), application, action (`deny`/`alert`/`monitor`/`quarantine`), group, and aggregated **count**. An **Advanced Filter** builds keyword + category queries (Network, Process, Package, Tunnel, File, Privilege) and that filter drives **CSV/PDF export**.
